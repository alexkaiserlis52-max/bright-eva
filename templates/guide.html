1 · What Bright E.V.A. is

Evaluation Virtual Assistant — AI report writing for a school, engineered for children’s data

Bright E.V.A. turns a school’s assessment forms into well-written progress reports: per student, per lesson, per class group. An educator picks an ID, states what to assess and in whose voice, and the system produces a grounded report in under two minutes.

What makes it unusual is not that it uses AI — it is how. Four principles govern every design decision:

PrincipleWhat it means in practice
Privacy first The students are minors. A deterministic anonymizer masks every name, email and phone number before any prompt is built. The AI only ever sees pseudonymous IDs such as demo02.
Human in the loop With Educator Override enabled, no report reaches the student record until an educator explicitly approves, edits or rejects it. The decision itself is audited.
Glass box Every run leaves a complete pipeline trace: data fetched, masks applied, exact prompts, critic verdicts, cost, timing, risk signals. Nothing the AI did is uninspectable.
Grounded output Reports must be traceable to real assessment data. A critic gate reviews each draft and can reject and regenerate it; risk signals hunt for what slipped through.

2 · The data layer

Google Sheets is the school’s database — deliberately

There is no hidden database server. The school already lives in Google Sheets, so E.V.A. treats those spreadsheets as the database: it reads assessment data from them and writes reports back to them. This keeps the data where educators already understand it — visible, editable, shareable through the tools they know.

3 · The report pipeline

What actually happens between “Generate Report” and the finished text

📥 1 · FetchThe student’s (or lesson’s, or group’s) rows are pulled from the relevant sheets. The whole Students registry is also loaded — as anonymizer vocabulary.
🛡️ 2 · ScrubThe anonymizer replaces every name (including Greek genitive forms), email and phone with placeholders like [Student] and [email]. Pseudonymous IDs are never masked.
🤖 3 · SummarizeEach assessment section is summarized by the AI — calls run in parallel, each seeing only anonymized slices.
✍️ 4 · SynthesizeA final AI call composes the report from the summaries, your focus question, the narrator role, and the active style profile or built-in gold exemplar.
🧐 5 · Critic gateA separate AI review asks: does it answer the question? Is every claim grounded in the data? Is it PII-free? A fail triggers exactly one regeneration with feedback.
🧠 6 · DistillThe approved report is compressed into a structured insight card — trajectory, trends, risk flags, evidence, takeaway.
⚠️ 7 · CompareThe new card is compared with the entity’s previous one. A worsening trajectory or new risk flags fire an early warning; otherwise the system stays deliberately quiet.
💾 8 · SaveWith approval mode on, the report is staged as a dry-run and waits for the educator’s approve / edit / reject. Only then are ReportsFile and InsightsMemory written — together.

Every one of these steps is recorded. Open any run under Pipeline to see it exactly as it happened — including the raw prompts.

C.2 · The six tools up close — what each one reads, what it returns, and how you trigger it

There is no AI inside the tools — each one is deterministic Python that reads a specific data source, scrubs the result and hands it back as compact JSON/text. The only AI decisions in the chat are (a) which tool to call with what arguments and (b) composing the final answer from whatever came back. The tools read across all three data levels — the raw sheets (L0), the saved reports (L1), the distilled insight cards (L2) — plus the school's Drive archive:

ToolReads fromWhat it hands back to the modelYou trigger it by asking…
get_student_overview Students registry (L0) · FoAssessment scores (L0) · latest insight card (L2) Age/class, group memberships, averages of the 5 formative dimensions (participation, comprehension, build, programming, collaboration), trend (last 3 vs first 3 sessions), up to 3 recent teacher notes, the latest insight card. «How is demo02 doing?» · «Is demo05 improving this term?»
search_insights InsightsMemory cards (L2) Keyword/entity-matched cards: date, trajectory, cognitive and soft-skill notes, risk flags, early-warning alerts, takeaway. «Which students show declining collaboration?» · «Any risk flags lately?»
get_class_climate LessonAssessment sessions (L0) · Students registry (L0) · latest class card (L2) Sessions assessed, average class response (1–5), average completion %, recent difficulties and notes, member IDs, the latest class insight. «What's the climate of group ΜΓ1?» · «What difficulties came up in ΜΒ2 recently?»
compare_students Same sources as the overview, ×2–8 students Side-by-side table: formative averages, trend and latest trajectory per student. «Compare demo02 and demo07» · «Who of these three struggles most with programming?»
generate_report The full report spine (L0 → L1 pipeline) run as a dry-run A complete fresh report for one student, class or lesson — the same machinery as the home-page generators. Slow (~1 min), called only when you explicitly ask for a full report, and never saved anywhere. «Generate a full report for demo05»
get_lesson_plan The school's Google Drive lesson archive The actual lesson outline (goals, phases, materials) for a track (ΜΒ, ΜΓ, ΜΔ, ΜΕ, ΜΛ) and lesson number — Google Docs exported as text, .docx parsed. «What's covered in ΜΓ lesson 22?» · «Fetch lesson 5 of ΜΔ and suggest changes»

Three properties make the loop safe to trust. Grounding: the system prompt forbids factual claims that did not come from a tool result, and students are referenced by ID only — every tool result is scrubbed before the model sees it. Boundedness: the loop runs at most 6 tool steps, then must answer; generate_report is always a dry-run, so chatting can never write to the school's sheets. Transparency: each tool call appears as a chip in the chat UI and the whole run leaves a pipeline trace you can open from the answer.

Chat or ASK ME? They answer different needs. The chat is interactive and quick: live facts, comparisons, follow-ups («…and how does that compare with demo07?» — it remembers the conversation; Clear resets it), and it can reach the Drive lesson plans — but it saves nothing. ASK ME is the opposite: one shot, over the saved reports only, producing a document you can archive to ReportsFile with the save switch. Rule of thumb: exploring → chat; producing something to keep → ASK ME.

5 · Anonymization — the GDPR core

How personal data is kept away from the AI

The anonymizer is deterministic — not an AI guessing what looks like a name. It is built from the Students registry itself: every known student and parent name (plus their Greek genitive forms, e.g. “του Νίκου”), every email pattern, every phone pattern. Because the vocabulary comes from the registry, even names of other students mentioned in a note are caught.

In the sheetsWhat the AI receives
Student & parent names (any inflection)[Student] · [Parent]
Email addresses[email]
Phone numbers[phone]
Pseudonymous IDs (demo02), Greek headers, π.μ./μ.μ., group codespassed through unchanged — they identify nothing on their own

The same scrubber guards every path to the AI: report generation, the chat’s tool results, and even Style Studio examples before distillation. Pipeline traces show a before/after sample of what was masked in each run, and the critic gate performs a second, independent PII check on the finished report — defense in depth.

6 · The AI layer

OpenRouter as the gateway — switchable models, visible terms, visible cost

All AI calls go through OpenRouter, an API gateway that fronts many model providers (OpenAI, Google, Anthropic and others). The model picker in the sidebar is a live list from OpenRouter: switching models changes every future run, and each pipeline trace records exactly which model was used, who provides it, and a link to that provider’s data policy.

Data termsEvery trace shows the provider’s data-usage terms next to the model, with a policy link. Prompts carry anonymized data only — but the terms are shown so nothing is taken on faith.
Cost transparencyTraces estimate cost from token counts × live OpenRouter prices (cached 6h), per model and per run. Education budgets should never be surprised.
Language policyEvery prompt begins with an explicit instruction: report prose in English, while Greek headers, IDs, π.μ./μ.μ. and group codes must be preserved verbatim as data keys.
Style controlFinal prompts embed a gold exemplar — or your own distilled style profile — with a hard rule: imitate the shape, never the example’s content.

7 · Smart Memory (L2)

From isolated reports to a longitudinal picture of each student

A single report says how a student did today. Smart Memory turns saved reports into a trajectory. Each approved report is distilled into a compact insight card:

Card fieldMeaning
trajectoryOne word — improving, stable, declining.
trendsThe few patterns that matter, each tied to evidence.
risk_flagsConcerns worth watching (e.g. disengagement, collaboration friction).
evidenceThe concrete observations backing every claim.
takeawayOne sentence an educator should remember.

Cards pass the same critic gate as reports before storage. Each new card is then compared with the previous one: a worsening trajectory or a new risk flag fires an early warning — the difference between a folder of reports and a safety net that notices a student quietly disengaging over weeks.

8 · Pages & tools

What each part of the app is for

PageWhat it does
Student / Lesson / Class ReportThe three generators on the home page. Pick an ID, a focus (“what to assess”), a narrator voice — get a grounded report. “Run for all students” batch-generates, one pipeline run each. The pickers list only entries that already have assessment data (a report cannot be generated without it); the “show all” switch on the hero reveals every registered entry — nothing is ever deleted, entries appear automatically once their form data arrives.
ASK MESmart queries over saved reports. Write the request in plain words (“a lesson plan for the class’s biggest weaknesses”, “adapt the lesson for this class”) — on Auto, E.V.A. routes it to the right pipeline: create or modify a lesson plan, “Find Solution” (one student vs. the class), or a general grounded answer. Class, lesson and student filters are all optional and simply narrow the evidence.
ChatFree-form questions. E.V.A. calls data tools (student profile, group climate, lesson content, comparisons) and answers strictly from what they return — every tool call is shown as a chip, and each answer links to its full pipeline trace.
Style StudioTeach the system your report style: paste an example report and/or plain instructions. One AI call distills them into a ≤250-word style profile; you review, edit and save it. Examples are anonymized before distillation and never stored.
PipelineThe glass box: every run with its data sources, masks, prompts, critic verdicts, memory writes, cost, timing and automated risk signals — plus a “Register a risk” form for human reviewers.
Risk RegisterThe living register: ten baseline risks (R1–R10) with their mitigations and the regulations they answer to — plus every observation reviewers registered on real traces, and unlisted risks gathering as candidates for the next revision.

9 · Safety & oversight

Layered — no single mechanism is trusted alone

Layer 1 · AnonymizerDeterministic masking before any prompt exists. Registry-derived vocabulary catches even other students’ names.
Layer 2 · Critic gateIndependent AI review of every report: grounding, question coverage, PII re-check. Fail → one regeneration with feedback.
Layer 3 · Educator OverrideWith approval mode on, reports are staged under a dry-run; only an explicit human decision writes anything. The decision joins the audit trail.
Layer 4 · Dry-run guardExperiments and staged reports are write-blocked at the data layer itself — safety by construction, not by convention.
Layer 5 · Risk signalsA deterministic second look over every trace: anonymizer off, gate skipped, silent fallbacks, ungrounded figures, quasi-identifiers, community-hosted models.
Layer 6 · Glass boxComplete traces make every layer inspectable — by the school, by auditors, by researchers.

The design assumption is that every layer can fail — which is why the register is alive: reviewers hunting on real traces register what they find, and the Risk Register documents honestly what remains hard (one model judging another shares its blind spots; pseudonyms are not anonymity in a small class).

10 · Glossary

The terms you will meet across the app

TermMeaning
Pipeline traceThe complete, immutable record of one run — events, prompts, verdicts, timings — written to disk as JSONL and rendered by the Pipeline pages.
Dry-runA run whose writes are blocked at the data layer. Used by Risk Lab experiments and staged educator approvals.
Anonymizer / scrubberThe deterministic component that masks names, emails and phones before any AI call. “Scrub vocabulary” = the registry-derived list of what to mask.
Pseudonymous IDAn identifier like demo02 that stands for a student without naming them. Not masked — but combined with date and group it narrows down a child (see “quasi-identifier”).
PIIPersonally Identifiable Information — anything that can identify a child: names, contacts, or enough combined detail.
Quasi-identifierData harmless alone (ID + date + class group) that identifies someone when combined — why pseudonyms are not anonymity.
Critic gateThe AI review step that must pass a report before it may be saved; rejection triggers one regeneration.
Insight cardThe structured Smart Memory record distilled from each saved report (trajectory, trends, risk flags, evidence, takeaway).
Early warningThe alert fired when a new insight card shows a worsening trajectory or new risk flags versus the previous card.
GroundingThe property that every claim in a report traces back to real assessment data — what the critic gate and the “unfound figures” risk signal check.
Style profileThe ≤250-word distillation of a report style (from an example and/or instructions), stored in StyleMemory and injected into final prompts.
Gold exemplarThe built-in default style sample used when no custom style profile exists.
OpenRouterThe API gateway through which all AI models are called — provides the model picker list, pricing and per-provider data policies.
TokenThe billing unit of AI models (~¾ of a word). Traces report prompt and completion tokens per call.
Educator OverrideApproval mode: nothing is saved until an educator approves, edits or rejects the staged report.
π.μ. / μ.μ.The school’s Greek rubric marks in assessment sheets — data keys, kept in Greek in every prompt and report.
Group codesClass-group identifiers like ΜΓ1 — data keys, kept in Greek.
Risk signalAn automated, deterministic flag on a trace (danger / warn / info) pointing at something a human should examine, linked to the Risk Register.
Risk lensThe auditor questions shown under each pipeline stage — what to doubt, not just what happened.
ENGLISH_ONLYThe language-policy preamble prepended to every prompt: prose in English, Greek data keys preserved verbatim.
